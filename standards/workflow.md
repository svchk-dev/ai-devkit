# Agent development workflow

Inspect the tree and preserve unrelated edits. Establish the authorized objective,
baseline, task-owned scope and required checks before editing. Read current
entry-point instructions, applicable scoped rules, full coding standards and
affected requirements/callers. Delivered references are not proof of comprehension.

Keep specifications, implementation and relevant documentation coherent. The
optional OpenSpec profile uses proposal/spec/design/tasks without requiring every
consumer to install OpenSpec. Structural validity and checked task boxes are not
implementation evidence.

Checks create evidence from actual execution, stable inputs, tool identity and
real exit/signal outcomes. Never claim running, skipped, failed or unavailable
checks as passing. Installed toolkit code/resources and adapter policy are inputs,
including development-linked content. Avoid repeated expensive validation after
each edit; edit-time hooks provide lightweight guidance and scope bookkeeping.

Before successful repository-changing completion obtain a separate independent
review of final actual changes and required checks. Supply objective, baseline,
owned changes, pre-existing edits and actual results. Reviewer findings identify
the governing rule, path/line, evidence and minimal correction. Personal
preferences are not defects. Reviewers do not edit or launch other agents.
Correct confirmed findings, rerun affected checks and obtain follow-up review
after substantive edits. Read-only work/reviewers do not require recursive review.

Hooks require explicit trust and actual client coverage. Missing/untrusted or
unsupported integrations retain manual obligations. Task state is local and
isolated by worktree/session/task, without credentials or full transcripts.
Completion distinguishes success, progress, waiting and incomplete work, respects
interruption and never expands authorization. No self-authored passed receipt
can substitute for an observed check or separate reviewer.

Keep changes local without explicit intended push/publication authorization.
Implementing, committing, preparing a version or discussing public hosting does
not authorize publication. Consult consumer release policy; shared guidance does
not import another product's version/tag workflow or deployment permissions.
